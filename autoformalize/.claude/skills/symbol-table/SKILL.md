# Writing symbol table entries

A symbol table (`.dkgf`) tells Informath how to say each Dedukti constant in
words and in formulas. One line per constant: the constant, a colon, and one
or more forms separated by `|`:

```
divides  : "#1 divides #2" | "#2 is divisible by #1" | $#1 \mid #2$
isGroup  : "#1 is a group"
htpy     : "homotopy from #3 to #4" | $#3 \sim #4$
ringZero : "the zero element of #1" | $0$
```

* A **verbal form** is an example in double quotes, parsed with Informath's
  grammar. `#k` is the k-th argument of the constant.
* A **symbolic form** is LaTeX in dollars. It becomes a macro
  (`\dividesMACRoA`) with as many parameters as the `#k` it uses.
* A form need not show every argument: `"homotopy from #3 to #4"` hides the
  first two (the types), and `$0$` hides the ring. Show what the source
  writes and leave out what it leaves implicit.
* Give both kinds of form whenever the source has both: the source's own words
  first, its own notation next. The first verbal form is the one used by
  default; with `-closest` the build picks among all of them the reading
  closest to the source's text.
* Comments are lines starting with `#` (or `(; ... ;)`). Lines starting with
  `#DROP`, `#MACRO` and the like are directives, not comments: don't start a
  comment with a directive's name.
* Theorems need no entry: their names are not used inside expressions.

## Which shape for which constant

The value type of the constant decides the category of its forms:

| Dedukti value type | category | verbal forms (examples) |
|---|---|---|
| `Prop` | Prop | `"#1 is even"`, `"#1 divides #2"`, `"#1 is a subgroup of #2"`, `"#1 and #2 are coprime"`, `"#1 is congruent to #2 modulo #3"` |
| `Set` (a type, a kind of object) | Kind | `"group"`, `"list of #1"`, `"homotopy from #3 to #4"`, `"subgroup of #1"` |
| `Elem A` (an object) | Exp | `"the empty set"`, `"the successor of #1"`, `"the sum of #1 and #2"`, `"the class of #3 modulo #2 in #1"` |

Shapes that parse, with `#1`, `#2`, ... for the arguments shown:

```
Prop:   "#1 is <Adj>"                     "#1 <Verb>s"
        "#1 is <Adj> <Prep> #2"           "#1 <Verb>s #2"   "#1 <Verb>s <Prep> #2"
        "#1 is a <Noun>"                  "#1 is a <Noun> <Prep> #2"
        "#1 and #2 are <Adj>"             "#1 and #2 <Verb>"
        "#1 is <Adj> <Prep> #2 <Prep> #3" "#1 is a <Noun> <Prep> #2 <Prep> #3"
        "#2 and #3 are <Adj> <Prep> #1"   "#1 is not <Adj>"   "#1 is not a <Noun> <Prep> #2"
Kind:   "<Noun>"   "<Noun> <Prep> #1"   "<Noun> <Prep> #1 <Prep> #2"   "<Noun> <Prep> #1 and #2"
Exp:    "the <Noun>"   "the <Noun> <Prep> #1"   "the <Noun> <Prep> #1 <Prep> #2"
        "the <Noun> <Prep> #1 and #2"   "the <Noun> <Prep> #1 <Prep> #2 <Prep> #3"
        "two", "three" (names; "zero" and "one" are nouns: "the zero")
Binders (a function argument x => B, its variable named in the form):
        "the <Noun> #1 of $x$"                              -- the union A of x
        "the <Noun> of #3 where $x$ ranges from #1 to #2"   -- sums, integrals
```

The verbs, adjectives and nouns must be words of the grammar: `"#1 and #2
meet"` parses, `"#1 and #2 intersect"` does not, as "intersect" is not a
word. A binder over a type ("... where $x$ is an element of #1") has no
example form: give such a constant a symbolic form (`$\bigcup_{x \in #1} #2$`
cannot be written either, as #2 is one argument; use `$\bigcup #2$` or ask
the user). Before relying on a shape, try it:

    echo '#1 and #2 meet' | RunInformath -parse-example    # prints the parse, or nothing

`<Noun>` can be a compound the grammar knows ("natural number", "two-sided
ideal"). The prepositions are of, from, to, on, in, by, with, into, onto, and,
as, among, under, over, at, between, modulo, with respect to, relative to,
generated by, spanned by, defined by, induced by, indexed by, associated with,
joining, of degree, of order, with coefficients in. To see all example shapes:

    RunInformath -all-gf-functions | grep Example

## Checking

    python3 scripts/check-table.py sec03.dkgf     # or no argument: all tables

* **CANNOT PARSE** -- a word is not in the grammar, or the shape is not one of
  the above. Find out which:

      echo "subgroup normal coprime" | RunInformath -find-gf   # the grammar's words
      echo '#1 is a subgroup of #2' | RunInformath -parse-example

  `-find-gf` prints `word :` with nothing after it for a word the grammar
  lacks. Then reword with a word it has, or add the word (the
  `grammar-extension` skill). A shape that does not parse cannot be fixed by
  adding words: choose another shape, or ask the user about extending the
  example forms.
* **MISMATCHING TYPES: c ("Prop",2) <> AdjPrepAdj2 ... (["Exp","Kind","Prop"],1)**
  -- the constant's value category and the number of arguments the form shows
  (left) do not fit the form (right). Usually a wrong #k or a Prop worded as a
  noun phrase. A constant whose value type is a function only by a definition
  (`Fam A := Elem A -> Set`) can give this falsely: the checker does not
  unfold definitions.
* **ARGUMENT OUT OF RANGE** -- the form uses `#k` beyond the constant's
  arguments. A function argument `(B : Elem A -> Set)` is *one* argument: it
  cannot be split into a variable `#2` and a body `#3` in a LaTeX form.
* The checker cannot tell *which* arguments a form shows: `"#2 is related to
  #3 by #1"` passes even if #1 is the set and #4 the second element. Check
  each `#k` against the constant's type yourself, and read the unit back.
* **NO ENTRY** -- a non-theorem constant without an entry; it reads as
  `\mathrm{c}(...)`. Fine for an auxiliary constant, not for a notion of the
  source.

Then read the unit back (`python3 scripts/build-informal.py sec03.dk` and
`-symbolic`) and look at the sentences: an entry can be well-typed and still
read badly.

## Getting close to the source

* Use the source's words: if it says "a is a multiple of b", that is the
  first form, even if "b divides a" is also right.
* Use the source's notation, with its macros if it has them (`$#1 \mid #2$`,
  `$\N$`). The source's macros are known to the index (items-macros.json).
* Name the hypotheses of the Dedukti types with the source's letters: the
  readings use them ("Let $G$ be a group").
* Run `build-informal.py -closest` and look at `secNN-closest.tsv`: a low
  similarity points to an entry, or a statement shape, that differs from the
  source.

## Pitfalls

* A predicate with a definite noun phrase does not parse: `"#1 is the inverse
  of #2"` fails; make the constant an Exp (`"the inverse of #2"`) and state
  equality with it, or use `"#1 is an inverse of #2"`.
* A two-place function noun is a noun plus prepositions and nothing more:
  `"the set of all subsets of #1 with #2 elements"` does not parse.
* A Prop worded as a name (`"the continuum hypothesis"`) is a type error:
  use `"the continuum hypothesis holds"` style wordings only if they parse,
  else give only a symbolic form.
* A negated definition (`notIn x y := not (In x y)` with `"#1 is not an
  element of #2"`) reads as a tautology: "x is not an element of y if x is
  not an element of y". Prefer to state `not (In x y)` directly.
* Macros are numbered over all tables in order (`base.dkgf`, `sec01.dkgf`,
  ...): adding a LaTeX form renames the macros after it, so rebuild all
  readings and the index together (the scripts do).
* `#DROP` lines conflict with example-based entries; hide arguments by not
  writing their `#k` instead.
* A name of Informath's base (`even`, `union`, `prime`, ...) already has an
  entry in `share/baseconstants.dkgf`; an entry in `base.dkgf` overrides it.
